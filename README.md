本项目记录一套面向大规模数据生产与 AI 训练的数据基础设施设计。目标场景同时包含小文件、聚合数据、模型文件和 Checkpoint，需要支持数据生产、版本发布、训练访问、多云协同与模型分发的完整链路。

文章重点讨论数据如何流动、存储系统如何分层、跨云副本如何建立、缓存如何选择性预热，以及不同文件系统和数据访问方案之间的工程取舍。文中的架构结论建立在当前业务约束之上，不将某一产品视为适用于所有场景的通用答案。

## 核心设计

- 存储链路分为远端存储层、缓存层、文件系统层和数据访问层；
- 一个“云厂商 × 地区”构成一个 `RegionNode`，同一云的不同地区也作为独立节点管理；
- 对象复制与元数据镜像是两条独立数据流，二者校验通过后，目标 `RegionReplica` 才进入 `READY`；
- 预热面向不可变的模型版本、数据集版本及 UserGroup 策略展开，缓存状态 `WARM` 不替代副本状态 `READY`；
- 控制平面统一管理版本、Manifest、权限、复制任务、预热任务和训练绑定；
- 架构选型比较自建 NAS、GPFS、CephFS、Alluxio 与 JuiceFS，并保留各方案的适用边界。

```text
数据生产
  → 源 RegionNode 发布不可变版本
  → 对象复制 + 元数据镜像
  → 目标 RegionReplica READY
  → UserGroup 权限校验
  → 模型 / 数据集选择性预热
  → 区域训练任务读取
  → Checkpoint 或模型输出登记为新版本
```
