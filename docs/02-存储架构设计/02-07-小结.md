Filesystem Layer 将对象存储中的对象转换为训练程序能够直接使用的文件和目录，并提供统一命名空间、元数据管理和多节点共享访问能力。
```
对象存储
   ↓
文件与对象映射
   ↓
统一命名空间
   ↓
POSIX 文件接口
   ↓
训练任务
```
它主要解决的是应用兼容性和数据管理问题，而 Cache Layer 主要解决访问性能问题，Remote Storage 则负责最终的数据可靠性和持久化。

三者共同组成完整的数据访问链路：
```
Training Layer
      ↓
Filesystem Layer
提供统一文件接口与命名空间
      ↓
Cache Layer
降低远程读取开销
      ↓
Remote Storage Layer
提供可靠、可扩展的持久化存储
```

在具体实践中，JuiceFS 将文件内容保存到对象存储，将命名空间和数据块映射保存到独立元数据服务，并通过客户端、CSI、本地缓存和分布式缓存向训练任务提供统一访问路径。

仅有数据访问链路还不足以管理正式训练版本。存储数据控制平面在数据面之外维护 DatasetVersion、Replica、Manifest、复制任务、校验任务和训练绑定，使数据集只有在目标区域完整复制并校验后才进入 `READY`。

因此，本章形成了两条相互配合的链路：

```text
数据面：对象存储 → 文件系统 → 缓存 → 训练任务

控制面：版本登记 → 复制 → 校验 → 就绪 → 训练准入 → 回收
```

对象存储提供长期可靠性，元数据服务和文件系统提供统一语义，缓存降低重复访问成本，控制平面保证版本、跨云副本和生命周期的正确性。后续的架构权衡与性能评估需要同时覆盖数据面和控制面，而不能只比较单个组件的峰值性能。
