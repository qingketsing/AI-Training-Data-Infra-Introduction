#### 2.6.1 控制平面与数据面

训练数据基础设施可以进一步划分为控制平面和数据面。

```text
                    数据控制平面
       版本、状态、策略、任务、审计与血缘
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
       复制任务         预热任务         回收任务
          │              │              │
          └──────────────┼──────────────┘
                         ▼
                       数据面
        对象存储、JuiceFS、缓存、网络与训练节点
```

数据面负责传输和保存真实字节，控制平面负责决定这些字节为什么被处理、处于什么状态以及谁可以使用。二者分离后，复制服务或缓存节点的短暂故障不会破坏权威版本记录；控制平面也不需要成为训练数据吞吐链路的一部分。

控制平面的主要职责包括：

* 管理数据集、模型和 Checkpoint 版本；
* 保存 Manifest、Schema、Tokenizer 和血缘信息；
* 编排跨云复制、校验、预热和清理任务；
* 判断版本是否具备训练准入条件；
* 管理幂等、重试、租约和并发限制；
* 提供权限、审批、审计与成本归属；
* 对外提供稳定的查询和操作 API；
* 汇总任务状态，但不替代监控指标系统。

#### 2.6.2 核心资源模型

控制平面至少需要以下逻辑资源。

| 资源 | 作用 | 关键字段 |
| --- | --- | --- |
| Dataset | 一个长期存在的数据集身份 | 名称、负责人、数据域、权限策略 |
| DatasetVersion | 一次不可变发布 | 版本、状态、Manifest、Schema、血缘 |
| Artifact | 模型、Tokenizer、索引或评测产物 | 类型、版本、对象位置、校验值 |
| Replica | 某个版本在目标存储中的副本 | 区域、Bucket、状态、最后校验时间 |
| TransferTask | 全量或增量复制任务 | 源、目标、幂等键、进度、重试次数 |
| VerificationTask | 数量、大小、哈希或消费校验 | 校验级别、结果、错误明细 |
| WarmupTask | 指定版本的缓存预热 | 缓存组、目标路径、字节进度 |
| TrainingBinding | 训练任务与数据版本的绑定 | 任务、版本、区域、只读凭证 |
| RetentionPolicy | 数据保留与删除策略 | 保留期、引用条件、审批策略 |

这些资源应使用稳定的全局 ID。名称可以修改，ID 和已经发布的版本号不能复用。

##### DatasetVersion

`DatasetVersion` 是控制平面的核心。一个版本发布后应保持不可变，任何内容、Schema 或 Tokenizer 变化都创建新版本。

```text
DatasetVersion
├── dataset_id
├── version
├── state
├── manifest_uri
├── manifest_digest
├── schema_version
├── tokenizer_version
├── lineage
├── created_by
└── created_at
```

Manifest 本身也需要校验摘要。如果只校验数据对象而不校验 Manifest，攻击、误操作或并发覆盖仍可能改变版本的实际含义。

##### Replica

同一个数据集版本可以在多个区域存在副本，但每个副本必须独立记录状态：

```text
Dataset v3
├── 主存储：READY
├── 云 A：READY
└── 云 B：VERIFYING
```

训练任务位于云 B 时，不能因为主存储已经 `READY` 就直接使用尚在校验的云 B 副本。训练准入需要同时检查版本状态、目标区域副本状态和必要的缓存状态。

#### 2.6.3 状态机

状态机应由控制平面统一执行，不能让复制脚本、人工操作和训练调度系统各自解释状态。

数据集版本可以采用：

```text
DRAFT → PUBLISHING → READY → DEPRECATED → DELETING → DELETED
             │
             └────────→ FAILED ────────→ PUBLISHING
```

各状态含义如下：

* `DRAFT`：允许数据生产任务写入，训练任务不可见；
* `PUBLISHING`：内容冻结，正在生成 Manifest 并执行校验；
* `READY`：校验通过，可以被授权训练任务绑定；
* `FAILED`：发布失败，保留错误明细，修复后可以重试；
* `DEPRECATED`：不再推荐新任务使用，现有引用仍然有效；
* `DELETING`：完成引用检查和保留期后正在清理；
* `DELETED`：数据已经删除，只保留必要的审计记录。

副本状态可以采用：

```text
ABSENT → COPYING → VERIFYING → READY
             │          │
             └──────────┴──→ FAILED
```

状态迁移必须是条件更新。例如，只有当前状态仍为 `COPYING` 且任务租约属于当前 Worker 时，才能更新为 `VERIFYING`。这样可以避免任务超时重试后，旧 Worker 使用过期结果覆盖新状态。

#### 2.6.4 数据集发布流程

一次完整发布流程如下：

```text
数据生产任务写入临时 Prefix
            ↓
关闭写入并生成 Manifest
            ↓
校验对象数量、大小、哈希与 Schema
            ↓
登记 DatasetVersion 和数据血缘
            ↓
版本状态切换为 READY
            ↓
按策略创建跨云复制任务
```

发布接口应接收幂等键。调用方因为超时重复提交时，控制平面返回同一个发布任务，而不是创建两个相互竞争的版本。

推荐的提交顺序是：

1. 数据写入任务专属临时位置；
2. 生成并持久化 Manifest；
3. 校验 Manifest 与对象；
4. 在控制平面事务中登记不可变版本；
5. 最后写入或暴露版本就绪标记；
6. 禁止继续写入已经发布的 Prefix。

对象存储不提供跨多个对象的通用事务，因此版本级状态就是对上层提供的提交边界。

#### 2.6.5 训练准入流程

训练任务不应直接接收任意对象存储路径。更安全的方式是提交数据集 ID、版本和目标区域，由控制平面解析实际位置并完成准入检查。

```text
训练任务请求 Dataset v3
          ↓
版本是否 READY？
          ↓
目标区域副本是否 READY？
    ┌─────┴─────┐
    │           │
   是           否
    │           ▼
    │       创建复制任务
    │           ↓
    │       校验并就绪
    └─────┬─────┘
          ↓
是否要求缓存预热？
          ↓
创建短期只读凭证和 TrainingBinding
          ↓
允许调度训练 Pod
```

训练绑定应固定版本，不能使用 `latest` 之类的可变别名作为最终运行参数。别名只能在任务提交时解析一次，并将解析出的版本写入任务记录。

#### 2.6.6 任务执行与幂等

复制、校验、预热和删除都属于长时间运行任务。控制平面需要支持：

* 幂等任务创建；
* Worker 租约和心跳；
* 进度游标；
* 可重试错误与永久错误分类；
* 指数退避和最大重试次数；
* 取消与超时；
* 死信任务和人工恢复；
* 单个源端、目标端和缓存组的并发限制。

任务记录保存控制状态，详细的高频指标和日志则进入监控与日志系统。不能把每个对象的实时传输指标都写入控制数据库，否则大规模复制会反过来压垮控制平面。

#### 2.6.7 一致性与并发控制

控制平面的关系型数据需要使用数据库事务保护以下约束：

* 同一数据集的版本号唯一；
* 同一副本只能存在一个活动复制任务；
* `READY` 版本必须关联校验通过的 Manifest；
* 仍被训练任务或模型引用的版本不能删除；
* 状态迁移必须符合状态机；
* 一个租约只能由当前持有者续期或完成。

跨数据库和对象存储无法使用单个本地事务时，应采用可恢复工作流：先记录意图，再执行外部操作，最后提交状态。后台对账任务周期性查找“控制状态与真实对象不一致”的资源并修复。

#### 2.6.8 权限与审计

控制平面自身不应保存长期明文对象存储密钥。训练任务通过工作负载身份或短期凭证访问指定 Prefix，并遵循最小权限：

* 数据生产任务可以写入临时 Prefix；
* 发布任务可以读取临时数据并写入正式版本；
* 训练任务只能读取绑定的数据集和模型版本；
* Checkpoint 任务只能写入当前任务目录；
* 删除任务使用单独角色并要求更严格审批。

审计记录至少包括操作者、时间、资源、原状态、目标状态、请求 ID、审批信息和结果。敏感凭证、个人信息和数据样本内容不能写入审计日志。

#### 2.6.9 可观测性与运行目标

控制平面需要暴露：

* 发布、复制、校验和预热任务的成功率与耗时；
* 各状态资源数量和最长停留时间；
* 任务队列深度、租约超时和重试次数；
* 每个区域的就绪版本数量；
* 数据集发布到目标区域就绪的端到端延迟；
* 训练任务因数据未就绪而等待或拒绝的次数；
* 版本删除前的引用检查结果；
* 按业务、区域和数据集归集的传输字节与成本。

告警应围绕业务结果设计。例如，单个对象重试通常不需要立即通知，但一个正式版本长时间停留在 `VERIFYING`、训练任务无法绑定或目标区域无可用副本时，需要触发告警。

#### 2.6.10 适用边界

数据控制平面解决的是跨组件的生命周期和一致性问题，不应承担以下职责：

* 不代理训练数据的实际读写流量；
* 不替代对象存储的持久化和容灾；
* 不替代 JuiceFS 元数据服务；
* 不替代 Kubernetes 调度器；
* 不把缓存副本提升为权威数据；
* 不以控制数据库状态替代真实对象校验。

控制平面的最终目标，是让每个训练任务都能回答三个问题：使用的是什么不可变版本、这个版本在当前区域是否完整可用、出现问题时能否追踪并恢复。
